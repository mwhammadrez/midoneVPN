# TunnelKit — ساخت VPN اندروید از صفر

مرحلهٔ ۱ ساخته و کامپایل شده. این سند هم راهنمای اجراست، هم توضیح اینکه یک VPN اندرویدی **واقعاً** از چه چیزهایی ساخته شده.

---

## ۱. یک VPN اندرویدی در پنج خط

هر اپ VPN روی اندروید، در نهایت همین است:

1. `VpnService.prepare()` → از کاربر اجازه می‌گیرد (آن دیالوگ آشنای «درخواست اتصال»).
2. `VpnService.Builder` → یک اینترفیس شبکهٔ مجازی (TUN) می‌سازد، با آدرس و روت.
3. `establish()` → یک **file descriptor** برمی‌گرداند.
4. روی آن fd، هر بار که اپ‌ها ترافیک می‌فرستند، یک **بستهٔ IP خام** می‌رسد؛ هرچه بنویسی، به دستگاه تزریق می‌شود.
5. سرویس باید foreground بماند، وگرنه سیستم می‌کشدش.

رمزنگاری، پروتکل، سرور — همه در گام ۴ اتفاق می‌افتند. خودِ اندروید هیچ پروتکلی به تو نمی‌دهد؛ فقط لوله را می‌دهد.

```
   اپ‌های دیگر (مرورگر، تلگرام، ...)
              │  بستهٔ IP
              ▼
   ┌──────────────────────┐
   │  TUN (fd)            │  ← اینجا کد ما می‌نشیند
   └──────────────────────┘
              │
   stage 1: فقط ping جواب می‌دهیم
   stage 2: بسته را به SOCKS5 / WireGuard می‌دهیم → سرور
```

## ۳. مرحلهٔ ۱ چه کاری می‌کند (و چه کاری نمی‌کند)

**می‌کند:** یک TUN واقعی بالا می‌آورد، به `10.111.0.1` جواب ping می‌دهد، هر بسته‌ای را که رد می‌شود در لاگ نشان می‌دهد. یعنی لوله واقعاً کار می‌کند.

**نمی‌کند:** ترافیک اینترنت را عبور نمی‌دهد. عمداً فقط روت `10.111.0.0/24` اضافه شده تا اینترنت گوشی قطع نشود. اگر همین حالا `0.0.0.0/0` بگذاری، همه‌چیز در تونل می‌رود و چون کسی جواب نمی‌دهد، گوشی بی‌اینترنت می‌شود — این همان جایی است که مرحلهٔ ۲ معنا پیدا می‌کند.

### تست دستی
1. APK را نصب کن.
2. `CONNECT` → اجازهٔ VPN را بده.
3. در Termux بزن: `ping 10.111.0.1`
4. در اپ باید خطوط `ICMP ... -> ...` و بعد `echo reply -> ...` را ببینی. پینگ جواب می‌دهد.

چرا این «اثبات» است: بستهٔ ping از کرنل به TUN می‌رود، کد ما آن را می‌خواند و دستی جواب می‌سازد، کرنل جواب را قبول می‌کند. یعنی تمام مسیر TUN → کد ما → TUN سالم است.

## ۵. مرحلهٔ ۲ — تصمیم اصلی

اینجا یک واقعیت مهندسی هست که باید قبل از انتخاب بدانی:

**تو نمی‌توانی بسته‌های TCP خام را «فوروارد» کنی.** اگر بستهٔ TCP از TUN بیرون بیاید، باید یک پشتهٔ TCP در فضای کاربر داشته باشی که three-way handshake را جواب بدهد، پنجره و retransmit را مدیریت کند. نوشتنش چند ماه کار است. همهٔ VPNهای تجاری هم همین کار را نمی‌کنند؛ از یکی از این دو راه می‌روند:

### گزینهٔ A — tun2socks (آموزشی‌تر، سبک‌تر)
روت `0.0.0.0/0` می‌دهی، و یک کتابخانهٔ آماده (`hev-socks5-tunnel` یا `badvpn`) بسته‌های TCP/UDP را به یک **پروکسی SOCKS5** تبدیل می‌کند. تو SOCKS5 را روی VPS خودت بالا می‌آوری و داخل یک تونل رمزنگاری‌شده (SSH یا WireGuard) می‌گذاری.
- مزیت: کل مسیر را لمس می‌کنی، کد خودت قابل فهم می‌ماند، حجم کم.
- عیب: کارایی و مصرف باتری متوسط؛ برای محصول نهایی ایده‌آل نیست.

### گزینهٔ B — WireGuard (مسیر محصول)
کتابخانهٔ رسمی `com.wireguard.android:tunnel` را اضافه می‌کنی؛ خودش handshake، رمزنگاری (ChaCha20-Poly1305)، و پمپ بسته را دارد. تو فقط کانفیگ را می‌دهی و UI می‌سازی.
- مزیت: امن، سریع، صفحات کم، باتری خوب.
- عیب: از «بیسیک» فاصله می‌گیری — جادو زیاد است.

### گزینهٔ C — پروتکل خودت (ToyVpn)
یک تونل UDP ساده که خودت بسته‌ها را کپسوله می‌کنی. برای یادگیری عالی، برای امنیت فاجعه (بدون رمزنگاری قابل شکستن است، بدون احراز هویت).

**پیشنهاد من:** A را برای یادگیری بزن (چون هر لایه را می‌بینی)، بعد B را برای نسخهٔ واقعی. یا اگر هدفت محصول است، مستقیم B.

## ۶. سمت سرور (لازم داری)

هیچ VPN بدون سرور کار نمی‌کند. حداقلِ کار:

```bash
# یک VPS ارزان (۱ هسته، ۱ گیگ کافی است)
apt install wireguard
wg genkey | tee server.key | wg pubkey > server.pub
# /etc/wireguard/wg0.conf → آدرس، پورت، peer
sysctl -w net.ipv4.ip_forward=1
wg-quick up wg0
# فایروال: فقط پورت UDP انتخابی + SSH باز باشد
```

برای گزینهٔ A: روی همان VPS یک SOCKS5 (مثلاً `danted`) که فقط به `127.0.0.1` گوش بدهد، و اپ از طریق SSH tunnel به آن وصل شود.

## ۷. اگر بخواهی در Google Play منتشر کنی

- اپ باید `VpnService` را در مانیفست اعلام کند (همین حالا هست).
- سیاست Play برای VPN: باید **هستهٔ کار** اپ VPN باشد، سیاست حریم خصوصی داشته باشی، و از جمع‌آوری داده برای تبلیغات منع شده‌ای.
- `targetSdk` جدید + `foregroundServiceType` درست (همین حالا هست).
- امضای release با keystore خودت.

## ۸. قدم بعدی

یکی را انتخاب کن:
- **A** → مرحلهٔ ۲ را با tun2socks و SOCKS5 می‌سازم (کد داخل اپ + راهنمای سرور).
- **B** → WireGuard را وصل می‌کنم و UI را تبدیل می‌کنم به مدیریت کانفیگ/پروفایل.
- **C** → ToyVpn کامل، فقط برای فهم.

## وضعیت فعلی پروژه (ممیزی ۲۰۲۶-۱۰-۲۴)

آنچه **واقعاً** کار می‌کند و تست دارد:

- موتور Xray با AAR رسمی `libXray v26.10.21`؛ مسیر TUN با `XRAY_TUN_FD`
- هماهنگ‌کنندهٔ واحد اتصال (تک‌موتوری، سوییچ امن، پاک‌سازی تضمینی)
- پارس و اعتبارسنجی `vless://` + تولید کانفیگ Xray
- تشخیص فرمت کانفیگ و پارس سابسکریپشن (با سقف حجم/تعداد)
- دریافت سابسکریپشن با محافظ SSRF و کش آخرین نسخهٔ سالم
- ۳۵ تست JVM + اسنپ‌شات UI

آنچه **هنوز نیست**: اسکنر endpoint، UI نهایی (طبق درخواست مالک بعداً)،
ذخیرهٔ رمزنگاری‌شدهٔ پروفایل، و هیچ تست اتصال واقعی.
